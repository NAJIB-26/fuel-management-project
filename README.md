# نظام مراقبة المحروقات والصيانة (FMS)

نظام إدارة أسطول شاحنات — طلبات محروقات، صيانة دورية وعامة، صلاحيات RBAC، تقارير.

## البنية

```
fms-project/
├── backend/     # Node.js + Express + TypeScript + Prisma + PostgreSQL
├── frontend/    # React + Vite + TypeScript + Tailwind (RTL)
├── mobile/      # Flutter (تطبيق السائقين)
└── docker-compose.yml
```

---

## الطريقة الأسهل: تشغيل عبر Docker (موصى بها)

### المتطلبات
- Docker + Docker Compose مثبتين على جهازك.

### الخطوات

```bash
# 1) فك ضغط المشروع والدخول للمجلد
cd fms-project

# 2) انسخ ملف البيئة وعدّل القيم (اختياري للتجربة المحلية)
cp .env.example .env

# 3) شغّل كامل النظام (قاعدة بيانات + API + واجهة)
docker compose up --build

# 4) في نافذة طرفية أخرى، وبعد أن يعمل الـ API، هيّئ قاعدة البيانات بالبيانات الأولية
docker compose exec api npx prisma db seed
```

### الوصول
- الواجهة (Frontend): http://localhost
- API مباشرة: http://localhost:4000/api
- تسجيل الدخول الافتراضي: **admin / Admin@12345**

لإيقاف النظام: `Ctrl+C` ثم `docker compose down` (أضف `-v` لحذف بيانات القاعدة أيضاً).

## التشغيل يدوياً بدون Docker

### المتطلبات
- Node.js 20+
- PostgreSQL 16+ يعمل محلياً

### 1) الباك-إند (Backend)

```bash
cd backend
npm install
cp .env.example .env
# عدّل DATABASE_URL في .env ليطابق قاعدة بياناتك المحلية

npx prisma generate
npx prisma migrate dev --name init
npx prisma db seed

npm run dev
```
يعمل على: http://localhost:4000

### 2) الواجهة الأمامية (Frontend)

افتح نافذة طرفية جديدة:
```bash
cd frontend
npm install
npm run dev
```
يعمل على: http://localhost:5173 (يوجّه تلقائياً طلبات `/api` إلى `localhost:4000`)

### 3) تسجيل الدخول
افتح المتصفح على `http://localhost:5173` وسجّل الدخول بـ:
- **اسم المستخدم:** admin
- **كلمة المرور:** Admin@12345

## تطبيق الجوال (Flutter)

### المتطلبات
- Flutter SDK مثبت (`flutter doctor` يجب أن يعمل بدون أخطاء حرجة)

### الخطوات
```bash
cd mobile
flutter pub get
```

عدّل السطر التالي في `lib/main.dart` ليشير لعنوان الخادم الفعلي لديك:
```dart
const String kApiBaseUrl = "http://10.0.2.2:4000"; // للمحاكي Android فقط
```
- لمحاكي Android: اترك `10.0.2.2` (يشير تلقائياً لـ localhost على جهازك).
- لجهاز حقيقي أو خادم عن بعد: استبدلها بعنوان IP أو الدومين الفعلي، مثل `http://192.168.1.10:4000` أو `https://your-domain.com`.

ثم شغّل التطبيق:
```bash
flutter run
```

## الوحدات المكتملة في هذا الأرشيف

- **المصادقة (Auth):** تسجيل دخول، JWT، `/auth/me` (يرجع الصلاحيات + المسؤول المباشر)
- **الشاحنات (Trucks):** إضافة/تعديل، نوع زيت المحرك، حدود الصيانة الدورية الديناميكية
- **طلبات المحروقات:** تاريخ قابل للتعديل، سعر الوحدة، المبلغ الإجمالي (آلي)، فارق العداد
- **الصيانة الدورية:** حساب الفارق مقابل الحد المسموح لكل نوع صيانة، اعتماد مستويين
- **الصيانة العامة:** سقف الاعتماد المالي، اعتماد مستويين
- **المستخدمون:** الرقم الوظيفي (أرقام فقط، اختياري)، ربط المسؤول المباشر
- **الصلاحيات (RBAC):** بحث عن مستخدم، صلاحيات تبويبات وشاشات، مدير نظام
- **تهيئة النظام:** بيانات الشركة، الوحدات، أنواع الصيانة والأعطال، الموردون
- **لوحة الإحصائيات ولوحة التتبع (Audit Log)**
- **الإشعارات:** تسجيل/إلغاء أجهزة FCM (Backend فقط في هذا الأرشيف)
- **الواجهة:** إخفاء تبويب/شاشات "تهيئة النظام" تلقائياً عن غير المخوّلين (عبر `AppShell` + `ScreenGuard`)، وحماية مطابقة على الخادم عبر `requireScreen`

## ملاحظات هامة

1. **غيّر كلمة مرور admin فوراً** في أي بيئة حقيقية.
2. **غيّر JWT_ACCESS_SECRET و JWT_REFRESH_SECRET** في ملف `.env` قبل النشر.
3. بعد فك الضغط، نفّذ `npx prisma migrate dev --name init` (وليس فقط `db seed`) لأن الـ schema يحتوي جداول جديدة (الصيانة الدورية/العامة، الوحدات، الموردون...).
4. تطبيق Flutter (`mobile/`) يغطي تسجيل الدخول/الخروج الأساسي فقط؛ شاشات الطلبات الميدانية والمزامنة دون اتصال وإشعارات FCM كاملة موثقة في سجل المحادثة ويمكن إضافتها بنفس الأسلوب.
